# QQ 聊天记录导出工具集原理分析

本工具集是一套用于解密后 QQ 本地数据库（`nt_msg.decrypt.db` 等）的 ORM 映射、消息 Protobuf 解析和多格式导出的 Python 脚本。整体采用 SQLAlchemy + Pydantic + blackboxprotobuf 实现，支持群聊和私聊消息的批量导出。

---

## 1. 整体目标

- 提供数据库 ORM 映射：将 QQ 本地 SQLite 表（列名多为数字）映射为可读的 Python 类，便于查询。  
- 解析 Protobuf 消息体：将 `msgBody` / `message_body` 字段中的二进制 Protobuf 数据解码为结构化的消息元素（文本、图片、文件等）。  
- 导出聊天记录：支持 JSON、CSV、TXT 三种格式，可导出所有群聊/私聊，或按群号筛选。

---

## 2. 数据库层设计

### 2.1 多数据库管理（`man.py`）

`DatabaseManager` 是一个单例类，负责管理多个 SQLite 数据库连接。  
通过 `register_model` 装饰器将模型类注册到对应的数据库标识（如 `"nt_msg"`、`"emoji"`、`"group_info"`、`"profile_info"`）。  
在 `__new__` 中检测是否存在 `{db_id}.decrypt.db` 文件，若存在则创建 SQLAlchemy Engine 并持有会话（`Session`）。  
提供 `group_messages()` 和 `c2c_messages()` 方法返回对应的 ORM Query 对象，便于链式过滤。

### 2.2 ORM 模型定义（`models.py`）

所有模型继承自 `DeclarativeBase`，使用 `Mapped` 和 `mapped_column` 定义字段。  
列名是实际数据库中的数字（如 `"40001"`），字段名赋予语义（如 `msgId`），映射关系通过 `query2orm.py` 辅助生成。  
涵盖了消息表（`group_msg_table`、`c2c_msg_table`）、表情表、群信息表、好友表等 30+ 张表，但导出功能目前仅用到群聊和私聊消息表。

### 2.3 自定义文本工厂

连接时设置 `text_factory = gbk_text_factory`，尝试用 GBK 解码字节数据（兼容老版本 QQ 可能使用的编码），失败则回退 UTF-8。

---

## 3. 消息解析层（`message.py`）

### 3.1 Protobuf 解码

使用 `blackboxprotobuf` 库解码 `msgBody`（或 `message_body`）字段的二进制数据。  
解码后的结构通常为：  
`{ "40800": [ {...}, {...} ] }`  // 元素列表  
每个元素内部包含 `"45002"` 字段，表示元素类型 ID（如 1=文本，2=图片，8=系统通知等）。

### 3.2 元素注册器（`ElementRegistry`）

使用装饰器 `@ElementRegistry.register(elem_id)` 将具体元素类注册到 ID。  
`decode` 方法根据 `data["45002"]` 查找对应类并调用其 `decode` 方法，若未找到则返回 `UnsupportedElement`。  
所有元素类继承自 `Element`（Pydantic 基类），必须实现 `decode` 和 `__str__`。

### 3.3 支持的元素类型

- **Text (1)**：提取 `45101` 字段的文本内容。  
- **Image (2)**：提取宽高、文件名、alt 等。  
- **File (3)**、**Audio (4)**、**Video (5)**：提取哈希和路径。  
- **Emoji (6)**：提取表情 ID。  
- **Reply (7)**：引用回复，递归解析被引用消息。  
- **SystemNotification (8)**：撤回通知等。  
- **RedPack (9)**：红包消息。  
- **App (10)**、**Sticker (11)**、**XML (16)** 等。

### 3.4 消息容器（`Message`）

包含 `ID`、`seq`（消息序号）和 `elements`（元素列表）。  
`from_db` 方法接收 ORM 对象（`GroupMessage` 或 `PrivateMessage`），解码 `msgBody` 并生成 `Message` 实例。  
`from_reply` 用于解析引用消息中的 `embed` 数据。

## 4. 导出流程（`main.py` 及变体）

### 4.1 群聊导出（`export_group_chat_records`）

1. 通过 `dbman.group_messages().with_entities(GroupMessage.groupUin).distinct()` 获取所有群号。  
2. 对每个群号，按 `msgSeq` 升序查询所有消息。  
3. 遍历每条记录：  
   - 调用 `Message.from_db(dbo)` 解析出元素列表。  
   - 构造字典，包含 msgId、msgSeq、发送者昵称、QQ号、时间戳、元素字符串（`str(elem)`）等。  
4. 根据 `export_format` 输出到 `group_chat_history_{群号}.{format}`。

### 4.2 私聊导出（`export_c2c_chat_records`）

类似流程，但查询 `c2c_messages()`，字段映射略有不同（如 `contact_qq` 代替 `groupUin`）。  
消息体解析使用 `blackboxprotobuf.decode_message(dbo.message_body)`，其结构略有差异（元素在 `"40800"` 下可能为列表或字典），代码做了兼容处理。

### 4.3 手动指定群号（`main-手动指定群号导出消息.py`）

直接设置 `target_group_uin` 变量，仅导出该群。

### 4.4 自动导出所有群聊（`main-自动导出全部群聊消息.py`）

与主脚本逻辑一致，但仅输出 JSON 格式。

## 5. 关键技术点

- **数字列名映射**：QQ 本地数据库为了混淆，列名采用纯数字，工具通过 `query2orm.py` 从表结构 SQL 中提取列名和类型，生成 ORM 字段映射代码，提高了可维护性。  
- **Protobuf 动态解码**：`blackboxprotobuf` 无需预定义 `.proto` 文件，而是根据二进制数据推断结构，非常适合解析 QQ 这种动态变化的协议。  
- **注册器模式**：元素类型通过注册器动态绑定，新增元素只需编写新类并注册，无需修改核心解码逻辑。  
- **类型安全**：使用 `pydantic` 基类，自动进行数据验证和序列化，便于后续处理。  
- **多格式导出**：支持 JSON（结构化）、TXT（纯文本可读）、CSV（表格），满足不同使用场景。

---

## 6. 适用范围与局限性

- **适用对象**：已通过其他方式（如内存提取密钥）解密得到 `nt_msg.decrypt.db` 等数据库文件的 QQ 本地数据。  
- **依赖**：需要 `blackboxprotobuf`、`sqlalchemy`、`pydantic` 等第三方库。  
- **兼容性**：QQ 版本更新可能导致 Protobuf 结构变化，需同步更新元素解析逻辑。  
- **性能**：全量导出大量消息时，内存占用较高，建议分批处理。

---

## 7. 总结

该工具集是一个典型的**逆向工程辅助工具**，通过 ORM 映射、动态 Protobuf 解析和注册器模式，将晦涩的 QQ 本地数据库转换为结构化、可导出的聊天记录。其模块化设计（数据库管理、消息解析、导出分离）使得代码易于扩展，可适配更多表或消息类型，是研究 QQ 数据格式的有力参考。
