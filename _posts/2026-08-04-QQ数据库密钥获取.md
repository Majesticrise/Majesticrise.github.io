# `qq.ps1` 脚本原理分析

该 PowerShell 脚本旨在从 QQ 的 `wrapper.node` 模块中定位加密密钥相关代码，并动态调试 QQ 进程以提取 SQLite 数据库加密密钥。其核心思想分为**静态分析**和**动态调试**两个阶段，结合了 PE 文件解析、反汇编模式匹配、Windows 调试 API 等技术。

---

## 1. 整体目标

- 定位目标字符串：在 `.rdata` 段中找到硬编码的格式化字符串 `"nt_sqlite3_key_v2: db=%p zDb=%s"`。
- 找到引用该字符串的 LEA 指令：在 `.text` 段中搜索使用 `RIP` 相对寻址加载该字符串地址的 `LEA` 指令。
- 确定所属函数：利用 PE 的异常目录（Exception Directory）中的函数表，找到包含该 LEA 指令的函数的起始 RVA。
- 动态提取密钥：启动 QQ 进程并附加调试器，在目标函数入口设置断点，当断点触发时读取 `R8` 寄存器指向的字符串（即密钥），并验证其为 16 位可打印 ASCII 字符串。

---

## 2. 静态分析阶段

### 2.1 PE 文件解析
- 读取 `wrapper.node`（64 位 PE 文件），验证 DOS 头（`MZ`）和 PE 签名（`PE\0\0`）。
- 解析 PE32+ 可选头，获取**映像基址**（`ImageBase`）和**数据目录**。
- 遍历节表，记录每个节的虚拟地址（RVA）、文件偏移、大小等信息，重点关注 `.rdata`、`.text` 和包含异常目录的节。

### 2.2 查找目标字符串
- 将目标字符串转换为字节数组 `"nt_sqlite3_key_v2: db=%p zDb=%s"`（ASCII 编码）。
- 在 `.rdata` 节的文件偏移范围内执行**暴力字节搜索**，定位该字符串的位置。
- 计算其在内存中的 RVA：  
  `StringRVA = .rdata.VirtualAddress + (文件偏移 - .rdata.PointerToRawData)`。

### 2.3 搜索引用该字符串的 LEA 指令
- 在 `.text` 节中查找特定的指令模式：`48 8D 05 <disp32>`（即 `REX.W + LEA rax/rcx/... [RIP+disp32]`）。
- 具体的搜索逻辑：
  - 扫描字节，寻找 `8D`（LEA 操作码），其前一个字节应为 `0x48`（REX.W 前缀，表示 64 位操作数）。
  - 检查紧随的 ModRM 字节，确保为 `05`（表示 RIP 相对寻址，且无基址寄存器）。
  - 读取后 4 字节的 `disp32`（有符号偏移），计算目标地址：  
    `目标RVA = 当前指令RVA + 指令长度(7) + disp32`。
- 若计算出的目标 RVA 等于之前找到的字符串 RVA，则该指令即为我们要找的 LEA 指令，记录其 RVA。

### 2.4 通过异常目录定位所属函数
- PE 的**异常目录**（`.pdata` 节）包含用于结构化异常处理（SEH）的函数表，每个条目记录一个函数的起始 RVA、结束 RVA 及 unwind 信息。
- 异常目录的 RVA 和大小来自可选头的数据目录索引 3。
- 获取异常目录所在节的基址，将其 RVA 转换为文件偏移，读取所有条目（每项 12 字节：BeginAddress, EndAddress, UnwindInfo）。
- 由于条目按起始地址升序排列，对该有序数组执行**二分查找**，找到满足 `BeginAddress <= leaRVA < EndAddress` 的条目。
- 命中条目的 `BeginAddress` 即为包含该 LEA 指令的函数的起始 RVA。

## 3. 动态调试阶段

### 3.1 启动调试进程
- 使用 `CreateProcessW` 以 `DEBUG_ONLY_THIS_PROCESS` 标志启动 `QQ.exe`，使当前进程成为其调试器。
- 等待调试事件循环开始。

### 3.2 等待 `wrapper.node` 加载
- 在调试循环中，当收到 `LOAD_DLL_DEBUG_EVENT` 时，调用 `CreateToolhelp32Snapshot` 枚举进程模块，检查 `wrapper.node` 是否已加载。
- 一旦找到，获取其加载基址，计算目标函数在内存中的实际地址：  
  `BreakpointAddress = wrapperBase + FunctionRVA`。

### 3.3 设置硬件/软件断点
- 在目标函数入口（即 `BreakpointAddress`）写入 `0xCC`（`INT 3` 指令）。
- 保存原始字节，以便断点触发后恢复，保证程序继续正常执行。

### 3.4 调试事件处理
调试循环等待各类事件，关键处理逻辑：

- **异常事件（`EXCEPTION_DEBUG_EVENT`）**：
  - 若异常代码为 `EXCEPTION_BREAKPOINT`（0x80000003），且异常地址等于断点地址，则触发我们的断点。
  - 触发后：
    1. 恢复原始字节（取消断点）。
    2. 读取当前线程上下文（`GetThreadContext`），获取寄存器值。
    3. 检查 `R8` 寄存器——按照目标函数的调用约定（微软 x64 的 `__fastcall`），该函数被调用时第二个参数（或某个参数）可能通过 `R8` 传递。此处推测 `R8` 指向密钥字符串指针。
    4. 从进程内存中读取 `R8` 指向的字符串，限定最大 256 字节。
    5. 验证该字符串是否为 16 个可打印 ASCII 字符（介于 32-126 之间）。若成立，则视为有效密钥并保存。
    6. 无论是否找到有效密钥，均设置**单步标志**（`EFlags` 的 `Trap Flag`），恢复线程继续执行，并在单步异常中重新安装断点，以确保不丢失断点。
- **单步异常**：清除陷阱标志，重新写入 `INT 3`，恢复断点。
- **进程退出事件**：结束调试循环。

### 3.5 密钥提取细节
- 使用 `ReadProcessMemory` 从目标进程读取字符串。
- 密钥格式固定为 16 个 ASCII 字符（通常是十六进制或 Base64 编码的原始密钥）。
- 提取成功后，通过 `TerminateProcess` 终止 QQ 进程（或让其自然退出）。

## 4. 关键技术点

### 4.1 RIP 相对寻址
64 位 Windows 程序中，指令 `LEA reg, [RIP+disp32]` 常用于加载全局数据地址（位置无关代码）。脚本利用这一特性精确定位到字符串引用点。

### 4.2 异常目录（`.pdata`）
异常目录中的函数表不仅用于异常处理，也提供了函数的边界信息。通过二分查找能快速定位任意地址所属的函数，这是静态分析的关键技巧。

### 4.3 调试 API 与 P/Invoke
脚本内嵌了 C# 代码，定义所有需要的结构体和 P/Invoke 函数（如 `CreateProcessW`, `WaitForDebugEvent`, `ContinueDebugEvent` 等），避免了 PowerShell 直接调用 `Add-Type` 时复杂结构体的对齐问题。

### 4.4 断点与单步配合
因为函数入口被修改为 `INT 3`，在断点触发后必须恢复原始指令，然后通过单步执行（Trap Flag）使 CPU 回到原始流程，并重新安装断点以实现持续监控。这种“一次性断点 + 单步恢复”是用户态调试器的常见模式。

### 4.5 自动环境检测
脚本通过注册表（`HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\QQ` 或 `NTQQ`）和文件系统探测 QQ 安装路径，无需手动指定。

---

## 5. 适用场景与局限性

- **适用对象**：腾讯 QQ NT 版本（Electron 架构），其中 `wrapper.node` 包含加密密钥的生成/访问逻辑。
- **调用约定依赖**：假设目标函数使用 `rcx`/`rdx`/`r8`/`r9` 传递前四个参数，且密钥通过 `r8` 返回。
- **版本兼容性**：若 QQ 更新后函数签名或字符串位置变动，脚本可能需要调整模式或偏移。
- **权限需求**：需以管理员权限运行（调试其他进程需要 `SeDebugPrivilege` 或相同权限）。

---

## 6. 总结

该脚本巧妙结合了静态 PE 分析和动态调试技术，实现了一种半自动化的密钥提取方法。它不仅适用于 QQ 特定的加密密钥提取，其框架也可推广到其他需要定位数据引用和动态拦截函数参数的分析场景。整个流程体现了 Windows 下逆向工程中常用的文件解析、指令模式匹配、调试器控制等核心技术。
