## 1. 功能概述

Wurst7 是一个以 **Fabric 客户端 Mod** 形态实现的 Minecraft 挂端（hacked client）：它在客户端进程内通过 **Mixin 字节码注入**钩住原版 `Minecraft`、`LocalPlayer`、`Connection` 等类，把原版的 tick / 渲染 / 输入 / 网络包 / 聊天流重定向到自建的 `EventManager` 事件总线（`net.wurstclient.event`），再由 156 个 `Hack` 模块订阅这些事件来修改玩家移动、方块交互、战斗、渲染与聊天行为。功能在游戏内通过 **ClickGUI 窗口、Navigator 搜索界面、TabGUI、快捷键绑定、`.命令` 聊天前缀** 五类入口触发，全部状态与配置持久化在 `.minecraft/wurst/` 目录的 10 余个 JSON 文件中。它是一个单例架构（`WurstClient.INSTANCE` 枚举单例）+ 反射注册（`HackList`/`CmdList`/`OtfList` 扫描自身字段）+ 事件驱动 + Mixin 直改的混合体，无独立启动器，随 Fabric 加载即生效。

按模块计数的功能面：战斗 24（KillAura 系、CrystalAura、AnchorAura 等）、移动 33（Flight、Jesus、NoClip、Step 等）、方块 26（Nuker 系、AutoBuild、Tunneller 等）、渲染 37（各类 ESP、X-Ray、Search 等）、聊天 7、物品 9、娱乐 7、其他 11（Timer、Reach、TooManyHax 等）。

### 2.2 初始化流程（模块加载机制）


`WurstClient.initialize()`（`src/main/java/net/wurstclient/WurstClient.java:78-141`）按以下顺序完成装配，全部持久化文件位于 `.minecraft/wurst/`（目录创建于 `WurstClient.java:143-159`）：

1. 捕获 `Minecraft` 实例并转型为 `IMinecraft` Mixin 接口（:82-83）；
2. `PlausibleAnalytics`（匿名统计，:86-88）；
3. `new EventManager(this)`（:90）；
4. `new HackList(enabled-hacks.json)` —— 仅构造 156 个 hack 字段，启用状态**延迟到首个游戏 tick** 才从 `enabled-hacks.json` 加载（`hack/HackList.java:225-233` 构造时注册一次性 `UpdateListener`）；
5. `CmdList`（52 命令）、`OtfList`（18 项）—— 两者均用**反射扫描自身以 `Cmd`/`Otf` 结尾的字段**填入忽略大小写的 `TreeMap`（`command/CmdList.java:78-95`）；
6. `SettingsFile(settings.json).load()`（:101-102）→ `tooManyHaxHack.loadBlockedHacksFile()`（:103）；
7. `KeybindList(keybinds.json)`（构造即加载，含 14 条默认键位，`keybinds/KeybindList.java:117-135`）；
8. `ClickGui(windows.json)`、`Navigator(preferences.json)`、`FriendsList(friends.json)`（:108-116）；
9. 注册核心常驻监听器：`CmdProcessor`→ChatOutputListener、`KeybindProcessor`→KeyPress/MouseButtonPress、`IngameHUD`→GUIRender、`RotationFaker`→Pre/PostMotion、`WurstUpdater`→Update（:120-136）；
10. `AltManager(alts.encrypted_json, 加密目录)`（:138-140）。

Hack 模块自身的启用入口统一收敛在 `Hack.setEnabled(boolean)`（`hack/Hack.java:84-105`）：

```java
// hack/Hack.java:84-105（摘录）
public final void setEnabled(boolean enabled) {
    if(this.enabled == enabled) return;
    TooManyHaxHack tooManyHax = WURST.getHax().tooManyHaxHack;
    if(enabled && tooManyHax.isEnabled() && tooManyHax.isBlocked(this))
        return;                                   // 黑名单拦截
    this.enabled = enabled;
    if(!(this instanceof NavigatorHack || this instanceof ClickGuiHack))
        WURST.getHud().getHackList().updateState(this);  // HUD 列表更新
    if(enabled) onEnable(); else onDisable();     // 子类钩子（注册/注销事件监听）
    if(stateSaved) WURST.getHax().saveEnabledHax();      // 持久化
}
```

### 2.3 事件系统

`EventManager`（`event/EventManager.java:20-141`）维护 `HashMap<Class<? extends Listener>, ArrayList<Listener>>`；静态 `fire(E)` 在 `wurst.isEnabled()==false` 时静默丢弃（:36-48），触发时复制监听器列表并过滤 null 以容忍跨线程增删（:59-67），任何监听器抛出的 `Throwable` 都会被包成 Minecraft `CrashReport` 使游戏崩溃（:71-81）——即**事件路径无静默吞异常**。25 种监听器（`events/` 目录）全部由 Mixin 从原版代码触发（见 2.4）。

### 2.5 命令系统入口

52 个命令（`commands/` 目录）全部经 `CmdProcessor` 触发；分发时先过 TooManyHax 黑名单（`CmdProcessor.java:49-55`），未找到命令 → `CmdNotFoundException.printToChat()`（:109-129，提示 `.help`/`.say`）；命令抛 `CmdException` → 红 `[ERROR]` 聊天反馈（`command/CmdError.java:20-23`），其他 `Throwable` → CrashReport 崩溃（:76-98）。命令列表 `.help`、语法由 `Command` 基类拼接（`command/Command.java:29-30,41-44`）。本版本**无本地 Tab 补全器**，补全仅存在于 AutoComplete（OpenAI）对 `CommandSuggestions` 的注入（`mixin/autocomplete/CommandSuggestionsMixin.java:26-50`）。

### 3.2 调用链 A：聊天命令（`.t killaura` 为例）

1. `mixin/ChatScreenMixin.java:33-59` — `@Inject` 于 `ChatScreen.handleChatInput` 中 `String.isEmpty` 调用点之后（可取消），构造 `ChatOutputEvent` 并 `EventManager.fire`；事件被取消时**仍调用 `addRecentChat`** 保留聊天历史（:49-52）。触发频率：每次玩家回车发送消息。
2. `command/CmdProcessor.java:30-41`（`onSentMessage`）— Wurst 未启用直接返回；消息 trim 后以 `.` 开头则 `event.cancel()` 并 `process(message.substring(1))`。主线程（聊天屏 tick）。
3. `command/CmdProcessor.java:43-63`（`process`）— `parseCmd` 经 `CmdList.getCmdByName`（`TreeMap`，key 为 `".name"`，`command/CmdList.java:97-100`）查表；TooManyHax 拦截；`runCmd` 按空格切分参数调 `cmd.call(args)`。
4. `commands/TCmd.java`（`.t`）— `WURST.getFeatureByName(name)`（`WurstClient.java:224-236`，依次查 Hack → Command → Otf）→ `doPrimaryAction()` → `Hack.setEnabled(!enabled)`。
5. `hack/Hack.java:84-105`（`setEnabled`）— HUD 更新 → `onEnable()`。
6. `hacks/KillauraHack.java:117-130`（`onEnable`）— 互斥关闭 9 个同类 aura hack（:117-125）→ `EVENTS.add(UpdateListener/HandleInputListener/RenderListener, this)`（:128-130）→ 自此每 tick/每帧被事件总线回调（见 3.3）。

### 3.3 调用链 B：每 tick hack 执行（以 Killaura 攻击为终点）

1. 原版 `Minecraft.tick()`（主线程，20 tick/s）→ `mixin/MinecraftMixin.java:86-97` 在 `Gui.overlay` 调用点 `@Inject` → `EventManager.fire(HandleInputEvent)`。该注入点刻意选在 `handleKeybinds()` 之前且绕过"无 GUI"判空，是输入驱动型 hack 的统一心跳。
2. 原版 `LocalPlayer.tick()` → `mixin/LocalPlayerMixin.java:74-84` 在 `AbstractClientPlayer.tick` 调用点 `@Inject` → `fire(UpdateEvent)`，且事件包裹在 `TempRealInput`（`InputFaker.java:70-84`）中以保证监听器读到真实按键；同文件 :50-72 在 `tick`/`rideTick` 首尾执行 InputFaker 输入交换（Freecam 场景把 `player.input` 换成空输入）。
3. `hacks/KillauraHack.java:145-180`（`onUpdate`）— 目标筛选（详见 5.1）。
4. `hacks/KillauraHack.java:182-193`（`onHandleInput`）— `MC.gameMode.attack(MC.player, target)` + `attackSwing.swing()` → 原版 `MultiPlayerGameMode.attack` 构造 `ServerboundInteractPacket` 经 `ClientCommonPacketListenerImpl.send` 发出。
5. 出站包双闸门：`mixin/ClientCommonPacketListenerImplMixin.java:27-38`（`@WrapOperation` → `PacketOutputEvent`，游戏逻辑层）与 `mixin/ConnectionMixin.java:89-101`（`@WrapMethod` → `ConnectionPacketOutputEvent`，Netty 发送层兜底，可取消/改写）。
6. 旋转欺骗回写：若步骤 3 调过 `RotationFaker.faceVectorPacket(hitVec)`（`RotationFaker.java:51-60`），则 `mixin/LocalPlayerMixin.java:86-91` 在 `sendPosition` 头部 `fire(PreMotionEvent)` → `RotationFaker.onPreMotion`（:27-37）把玩家 yaw/pitch 临时改为 `serverYaw/serverPitch` → 原版据此构造移动包发出 → `sendPosition` 尾部 `fire(PostMotionEvent)` → `onPostMotion`（:40-49）恢复真实视角并清除标志。**单 tick 单包级欺骗，客户端视角不抖动**。
7. `mixin/ConnectionMixin.java:43-64`（`doSendPacket` HEAD）— 状态机 `sentPositionThisTick`：同一 tick 检测到第 2 个 `ServerboundMovePlayerPacket` 时先自动补发 `ServerboundClientTickEndPacket`（适配 26.3 快照服务端"每 tick 一位置包"校验；NoFall/Criticals/MaceDMG 等多发位置包 hack 依赖此兼容层）。

### 3.4 调用链 C：Mixin 直改型（无事件，例：Jesus 水上行走）

1. 原版方块碰撞查询 `BlockStateBase.getCollisionShape` → `mixin/jesus/BlockStateBaseMixin.java` `@Inject HEAD` 可取消 — 当方块含流体、`jesusHack.shouldBeSolid()`（`hacks/JesusHack.java:177-182`：启用 + fallDistance≤3 + 未潜行 + 不在水中）且上下文为本机玩家时，返回 `Shapes.block()` 整块固体碰撞箱 → **客户端物理层直接把水当地面**。
2. `hacks/JesusHack.java:63-89`（UpdateListener）— 在液体中设 y 速度 0.11 上浮；tickTimer 0/1 时分别设 0.30/0 模拟跃出水面。

### 4.1 Feature 继承体系

```java
public abstract class Feature {          // Feature.java:23
    LinkedHashMap<String, Setting> settings;   // :30（key=小写设置名）
    LinkedHashSet<PossibleKeybind> possibleKeybinds; // :32

    abstract String getPrimaryAction();  // :51

    // 静态快捷引用 WURST / EVENTS / MC / IMC  :25-28
}
```

## 5. 关键流程详解

### 5.1 Killaura：目标筛选 → 冷却 → 假旋转 → 攻击（COMBAT 代表）

`hacks/KillauraHack.java`（`super("Killaura")`，:97-98）。onEnable 互斥关闭 AimAssist/ClickAura/CrystalAura/FightBot/KillauraLegit/MultiAura/Protect/TriggerBot/TP-Aura（:117-125）并注册 Update/HandleInput/Render 监听（:128-130）。

**① 目标筛选管线**（`onUpdate`，每 tick，:145-180）：

```java
// KillauraHack.java:154-179（摘录）
Stream<Entity> stream = EntityUtils.getMeleeAttackableEntities();
stream = stream.filter(e -> EntityUtils.distanceToHitboxSq(e) <= rangeSq);  // range 默认 5
if(fov < 360) stream = stream.filter(...getAngleToLookVec(...) <= fov/2);  // FOV 30~360
stream = entityFilters.applyTo(stream);   // 25+ 实体过滤器（好友过滤在 EntityUtils.java:89）
target = stream.min(priority.getSelected().comparator).orElse(null);       // DISTANCE/ANGLE/HEALTH，默认 ANGLE
if(checkLOS && !BlockUtils.hasLineOfSight(hitVec)) target = null;          // 可选视线
WURST.getRotationFaker().faceVectorPacket(hitVec);                          // 服务器侧假旋转
```

**② 攻速冷却与随机化**（`settings/AttackSpeedSliderSetting.java:48-79`）：`tickTimer = 1000/speed + gaussian × maxRandMS`，每 tick 递减 50ms；`speed<=0`（auto 档）改用原版 `getAttackStrengthScale(0)<1` 蓄力判定。Killaura 每次攻击后 `speed.resetTimer(speedRandMS.getValue())`（:192）。源码设置项描述原文注明：`±100ms 可通过 Vulcan，0 可通过 NCP+/AAC/Grim/Verus/Spartan/vanilla`（`AttackSpeedSliderSetting.java:53-60`）——此为源码自带说明，本文仅转述。

**③ 攻击执行**（`onHandleInput`，:182-193）：`MC.gameMode.attack(MC.player, target)` + `attackSwing.swing()`（挥手方式可设 CLIENT/SERVER/OFF）后置 `target=null`——选目标与出手分离到不同事件阶段，保证包序贴近原版输入时序。

**④ 假旋转生命周期**（`RotationFaker.java:27-60`，已在 3.3 第 6 步展开）：`faceVectorPacket` 只改下一个移动包，`limitAngleChange` 限制单次转向角速度；`faceVectorClient`（:62-70）则直接改真实视角（KillauraLegit/NukerLegit 用，配合 `slowlyTurnTowards` 逐 tick 转头，`KillauraLegitHack.java:226-259` 还把差值叠加进鼠标增量事件，模拟真人转视角）。

**异常路径**：全程无 catch；任何异常经 EventManager 包成 CrashReport 崩溃客户端。

### 5.2 NoFall / AntiHunger / MaceDMG：onGround 与位移包伪造（MOVEMENT/COMBAT 代表）

- **NoFall**（`hacks/NoFallHack.java:73-82`）：不修改原移动包，而是每 tick **额外补发** `ServerboundMovePlayerPacket.StatusOnly(true, horizontalCollision)`（:80-81）使服务端 fallDistance 清零。暂停条件（`isPaused`，:84-114）：创造无敌、鞘翅滑翔（除非 allowElytra）、手持 Mace 且 pauseForMace（保留坠击伤害）、fallDistance 低于阈值（地面/鞘翅分别用 `minFallDistance`/`minFallDistanceElytra`，:100-106）、下落速度 ≥ −0.5（:109-111）。onEnable 先关 AntiHunger（:63，两者都依赖 onGround 欺骗，互斥）。
- **AntiHunger**（`hacks/AntiHungerHack.java:42-54`，PacketOutputListener）：把 `ServerboundMovePlayerPacket` 的 onGround 改为 false（着地且未坠落时），阻止服务端疾跑饥饿判定。
- **MaceDMG**（`hacks/MaceDmgHack.java:44-65`，PlayerAttacksEntityListener）：攻击命中且持 MACE 时连发伪造 y 序列——4×`sendFakeY(0)` 重置服务端累计位移 → `sendFakeY(√500)`（注释指明数字取自 `ServerGamePacketListenerImpl.handleMovePlayer()` 的检查阈值）→ 归零，骗服务端按坠落计算重锤伤害。
- **Criticals**（`hacks/CriticalsHack.java:87-93`）：PACKET 模式连发 y 偏移 0.0625/0/1.1e-5/0 的位置包满足服务端暴击"空中"判定。

以上多发位置包的 hack 均依赖 `ConnectionMixin.java:43-64` 的每 tick 位置包计数补发 `ServerboundClientTickEndPacket`（见 3.3 第 7 步）。

### 5.3 启动配置恢复链（CONFIG 代表）

`HackList` 构造尾部注册一次性 `UpdateListener`（`hack/HackList.java:228-233`）：首个游戏 tick（确保 MC 完全就绪）执行 `enabledHacksFile.load(this)`（`hack/EnabledHacksFile.java:64-86`）——先全部禁用再按文件启用，期间 `disableSaving=true` 防递归保存。加载完成后该监听器自行注销。顺序依赖：settings.json 必须先于 toomanyhax.json（:102-103，屏蔽名单先于状态恢复生效），enabled-hacks.json 最后（等 MC 就绪）。任何 hack 状态变化触发 `saveEnabledHax()` 全量重写（`Hack.java:103-104`）。

### 5.4 多线程区块搜索管线（RENDER 代表：Search / X-Ray 同类）

`hacks/SearchHack.java:90-104`（onEnable）：创建 `ForkJoinPool` + `ChunkSearcherCoordinator`（后者作为 PacketInputListener 在 Netty 线程把受影响区块加入 `chunksToUpdate` 增量重扫，`util/chunk/ChunkSearcherCoordinator.java:33-39`）。每个 `ChunkSearcher` 是一个 `CompletableFuture.supplyAsync` 任务，跑在最低优先级固定线程池（`ChunkSearcher.java:30-54`），循环内检查 `interrupted` 标志实现协作式取消（:69-94）。渲染侧两阶段异步：`getMatchingBlocksTask`（按眼距排序 + `limit=10^slider` 截断，对数滑条 3~6）→ `compileVerticesTask`（`BlockVertexCompiler`）→ 主线程上传 VBO（`SearchHack.java:201-248`）。onDisable `forkJoinPool.shutdownNow()` + 关闭顶点缓冲（:113-119）。错误路径：结果数达到 limit 时输出一次性警告"found A LOT of blocks"（:221-224），无异常捕获。

## 7. 边界条件与风险点（仅源码事实）

### 7.1 源码显式处理的边界

- **空值/前置校验**：`Hack.getRenderName` 注释明示"可能在 MC.player 为 null 时被调用"（`Hack.java:49`）；`EventManager.fire` 在未初始化时静默返回（:36-43）；OpenAI key 缺失 → 报错自禁用（`AutoCompleteHack.java:56-63`）；RemoteView 找不到实体 → error + 自关（`RemoteViewHack.java:74-80`）。
- **游戏模式判定**：ItemGenerator/KillPotion/TrollPotion/CrashChest/CopyItem/Enchant/Repair/Give 等要求 `hasInfiniteMaterials()`（创造），否则 error 自关；CrashChest 仅构造 40000 空tag 物品放鞋槽。
- **距离阈值**：放置类统一 4.25 格²（ScaffoldWalk:153）；KillauraLegit/NukerLegit/TriggerBot/TpAura range 上限压到 4.25（原版触及）；NoClip 常量 √500/√1500 直接引用服务端 `handleMovePlayer` 检查值（`NoClipHack.java:42-43`）。
- **冷却/计时**：`MC.rightClickDelay=4` 遵守原版右键间隔（多数放置 hack）；AttackSpeed 毫秒级冷却 + 高斯随机；AutoFish castRod/reelIn/patience（60s 超时重抛）；WurstUpdater 每会话仅检查一次。
- **维度/环境判定**：AnchorAura 检查 `RESPAWN_ANCHOR_WORKS` 维度否则自关（:107-112）；AutoLibrarian 状态机断言用 IllegalStateException。
- **服务器拒绝**：MassTPA 解析 "/help|permission" 判定命令无效（可忽略或停止）、"accepted...request" 判定成功；ForceOp 监听 op 失败/成功消息驱动重试；AutoLeave 低血量自动 `disconnect`。
- **线程中断**：ChunkSearcher 协作式 interrupted 标志；AutoSteal/FishingSpotManager 恢复中断位；ForkJoinTask.cancel。
- **多线程安全**：`EventManager.fireImpl` 复制列表 + 过滤 null（:59-67）；MobSpawnESP 的 HitboxCheckSetting 提供 OFF/SLOW(synchronized)/UNSTABLE 三档并在描述中警告后台线程使用 UNSTABLE 的风险（默认 OFF，`mobspawnesp/HitboxCheckSetting.java:29-30`）。
- **安全细节**：翻译加载校验资源 `KnownPack` 防恶意服务器资源包探测（`WurstTranslator.java:227-236`）；DownloadQueueMixin 按账户 UUID 隔离缓存防指纹（源码注释 #1226）；`~/.Wurst encryption` 写防钓鱼 README（`Encryption.java:91-98`）；遥测明示不采集个人信息且 dev/gametest 不发送（`PlausibleAnalytics.java:36-44,140-144`）；ServerNameResolverMixin 处理 Mojang 影子封禁重定向。

### 7.2 源码未处理/潜在边界（`[推断]` 项移至第 8 节）

事实性风险（源码可见的行为后果）：

- **事件异常即崩溃**：任何监听器抛错（如服务器发来意外包结构导致 ClassCastException）→ CrashReport 全客户端崩溃，无单模块隔离/自动禁用机制（`EventManager.java:71-81`）。
- **PacketInputEvent 在 Netty 线程回调 hack 代码**：NewChunks/AutoFish/BaseFinder 等在该线程直接读 `MC.level` 世界数据，与主线程世界加载/卸载存在数据竞争窗口（源码仅对 HitboxCheck 做了 synchronized 选项，其余未加锁）。
- **enabled-hacks.json 首 tick 恢复**：恢复前的一个 tick 内 hack 的 onEnable 在世界尚未完全就绪时运行（`HackList.java:229-233`），依赖各 hack 自身判空。
- **一次性创造物品**（CrashChest 40000 tag、KillPotion amplifier 125、TrollPotion Integer.MAX_VALUE 时长）在生存服务器发包可能被直接踢出或封禁——源码仅做"创造模式"前置校验，无服务器侧后果处理。
- **Timer 改 `deltaTicks` 影响整局**（含动画/粒子/冷却），无白名单隔离。
- **SneakHack 的 PACKET 模式在本版本被注释掉**（`SneakHack.java:91-127` 代码注释状态），仅剩 LEGIT；SpeedHack 也已删除模式枚举为单一实现——存在"设置残留旧值"的迁移问题（EnumSetting.fromJson 按名字匹配，未知名被丢弃，`EnumSetting.java:116-129`）。
