## A. 核心流程图（文字图）

### A1. tick 内事件顺序（对照 Wurst 的 HandleInput→Update→PreMotion）

```
Minecraft.tick()                                    主线程 20/s
├─ TickEvent.Pre                       (MinecraftMixin.java:121)
│    └─ 模块 onTickPre（KillAura 选目标/战斗aura）
│    └─ BlockIterator 回调（LOWEST-1，保证模块注册后同 tick 末执行）
├─ ... 原版 tick（玩家/世界/键鼠）...
├─ TickEvent.Post                      (:131)
│    └─ 模块 onTickPost（Step/Parkour/移动修正）
│
└─ LocalPlayer.sendPosition/sendChanges  (LocalPlayerMixin.java:173-191)
     ├─ SendMovementPacketsEvent.Pre  ── Rotations 队列在此应用假旋转,
     │     Speed/Velocity 在此改向量
     ├─ 发出 ServerboundMovePlayerPacket
     └─ SendMovementPacketsEvent.Post ── Rotations 运行 callback+补发 Rot 包
```

### A7. Rotations 旋转队列生命周期（与 Wurst 单 tick spoof 对比，详见 B1）

```
rotate(yaw,pitch,priority,callback) 入队(按 priority 降序)
    |
SendMovementPacketsEvent.Pre:  队首项 → 临时改客户端视角 → serverYaw/Pitch
    |                            (随移动包发出)
sendPosition 发包
    |
SendMovementPacketsEvent.Post: 运行队首 callback(动作包跟在旋转包后)
    |                           还原真实视角
    |                           队列剩余项 → 逐个发独立 Rot 包 + 各自 callback
    |
队列空但有 lastRotation → 持续 spoof 同角度 rotationHoldTicks(默认 4, Config)
```

## B. 工具层算法深读（Meteor 版"BlockBreaker/PathFinder 章节"）

### B1. Rotations — 优先级旋转队列（`utils/player/Rotations.java`）

- `rotate()`（:53-58）：从对象池取 Rotation，**按 priority 降序插入 ArrayList**，无去重——同 tick 多请求共存。
- Pre 阶段（:87-112）：监听 SendMovementPacketsEvent.Pre，取队首 → `setupMovementPacketRotation`（:114-117）临时改客户端视角+写 `serverYaw/serverPitch`。
- **双包机制**（Post :128-155）：队首项的旋转随移动包发出并运行其 callback（动作包跟在旋转包后）；**队列剩余项逐个发独立 `ServerboundMovePlayerPacket.Rot` 包**（:138-148），各带 callback——一 tick 内多次转向合法化为"移动包+追加 Rot 包"序列。
- **Hold**：队列空时若 lastRotation 未超 `rotationHoldTicks`（Config 默认 4）持续 spoof 同角度（:101-111）。
- **与 Wurst RotationFaker 对比**：Wurst 是"单次 spoof、单包"；Meteor 是"优先级队列+回调时序保证+跨 tick hold+多目标排队"——支持一 tick 内"转向 A 打一击、转向 B 放一块"的复杂序列 `[推断]`（CrystalAura 同 tick 放+打依赖此能力）。

### B2. InvUtils — 背包操作 DSL（`utils/player/InvUtils.java` + `SlotUtils.java`）

- **move() 链**：`move()` 设 PICKUP+two=true（:167-171）→ `from(index)` 经 `SlotUtils.indexToId` 转屏幕槽 id（:231-233）→ `to()` 触发 run()：click(from)+click(to)（:330-333），底层 `handleContainerInput(containerId, id, button, type, player)`（:353-355）。
- **槽位映射**（`SlotUtils.indexToId:52-81`）：玩家背包 index 0-40 → 各屏幕 id（生存背包 hotbar=36+i、offhand=45；箱子 hotbar=(rows+3)×9+i）。
- **quickSwap**（:182-185,325-328）：SWAP 类型，`data=from; from=to`——对目标槽执行一次 SWAP 点击（button=热栏序号编码），无光标占用。
- **防漏拿保护**（:346-350）：PICKUP 双击后光标仍持物（目标槽非空发生交换）→ 递归 click 放回原槽。
- **跨 tick 归还**：`swap(slot, swapBack)` 记录 previousSlot，`swapBack()` 还原并 `meteor$syncSelected()` 同步携带槽位包。

### B3. DamageUtils — 服务端同源伤害公式（`utils/entity/DamageUtils.java`）

- `explosionDamage`（:90-99）**复刻 `ExplosionDamageCalculator#getEntityDamageAmount`**：距离/威力→exposure→`impact=(1−d/power)×exposure`→`damage=(impact²+impact)/2×7×power+1`（:96；水晶 power=12、床/锚=10，:76-82）。
- **遮挡采样** `getExposure`（:361-404）复刻 `ServerExplosion#getSeenPercent`：按实体 AABB 每轴 `1/(2×diff+1)` 步长网格采样 raycast；**遮挡工厂 HIT_FACTORY :65-70——`getExplosionResistance() < 600` 的方块一律不算遮挡**（只有黑曜石/基岩级挡水晶），大幅提速；支持预测放置的黑曜石（:142-153）。
- **减免链** `calculateReductions`（:276-295）：难度缩放→护甲 `CombatRules.getDamageAfterAbsorb`→抗性 `1−lvl×0.2`→保护附魔（爆炸保护 ×2 累加 :304-343）。
- `fallDamage`（:248-261）：高度图快速路径，`(y−surface+fallDistance−3)` 减跳跃提升。
- **为什么复刻服务端**：`[推断]` CrystalAura/AutoLog/AutoTotem 的"目标伤害/自伤预估"必须与服务端结算一致，否则放空炮/误判自杀。

### B4. TargetUtils / EntityUtils / SortPriority（`utils/entity/`）

- `TargetUtils.getList`（:41-57）：遍历 `entitiesForRendering`+FakePlayerManager → sort(priority) → **subList 截断**（注释 "fast list trimming" :53）。
- SortPriority 比较器（`SortPriority.java:17-61`）：LowestDistance=平方距离；LowestHealth=getHealth（非 Living 排后）；ClosestAngle=**yawΔ²+pitchΔ² 最小**（视角误差最小优先）。
- `EntityUtils.intersectsWithEntity`（:245-294）：mixin 直达 `EntitySectionStorage` 按 section 迭代首中即返（注释 "Fast implementation" :248）。

### B5. BlockUtils.place — 放置流程（`utils/world/BlockUtils.java:90-131`）

```
① 槽位校验(:91) → ② 实体碰撞检查(:93-96) → ③ getPlaceSide 选面(:101)
④ 邻居=blockPos.relative(side), hitPos=面中心偏0.5(:107-108); 无面则贴自身+UP
⑤ BHR 用 side.getOpposite()(:111)
⑥ rotate 时 Rotations.rotate(yaw,pitch,priority, callback)（:113-120）
   callback 内 InvUtils.swap → interact → swapBack   ← callback 在旋转包发出后执行
```
- **面选择 vs Wurst 三级优先**：Meteor 用单次 `relevancy = lookVec 在面法线轴的分量`取最大（:184）——即最"面向玩家"的面；潜行处理在 interact 内**强制取消潜行再 useItemOn，PREDICTED 时挥手，随后恢复**（:133-146）。
- `isClickable`（:295-310）：工作台/砧/门枚举，避免对着可交互方块放块。

### B6. BlockIterator — 单 tick 生命周期迭代器（`utils/world/BlockIterator.java`）

- `register(h,v,fn)`（:85-96）：取全部 callback 最大半径为全局面半径。
- **在 TickEvent.Pre 的 priority LOWEST−1 执行**（:43-83）——保证模块的 Pre 注册后同一 tick 末尾统一扫描；x,z 外圈、y 内层遍历玩家为中心盒，每 callback 自过滤 `dx≤h && dy≤v && dz≤h`（盒形非球形 :63-70）。
- `disableCurrent()` 在遍历中注销当前 callback（:98-100）；每 tick 末清空 callbacks+执行 after() Runnable（:78-82）——**注册是一次性订阅，生命周期=一个 tick**；无每 tick 预算（全盒一次扫完）`[推断: 半径由模块自控]`。

### B7. TickRate — TPS 估算（`utils/world/TickRate.java`）

- 采样每个 `ClientboundSetTimePacket`（服务端 1/s）间隔，`tickRates[nextIndex]=clamp(20/elapsed,0,20)`（:34-42）；**环形窗口长度 20**（:24）；非零样本均值；进服 4 秒内直接返回 20（:51-64）。
- 源码注释：**复制自 KAMI Blue LagCompensator**（:19）——演进考古素材。
- 消费：pause-on-lag（KillAura/CrystalAura/HighwayBuilder）、AutoLog、Starscript `server.tps`。

### B8. MeteorExecutor + Http（`utils/network/`）

- MeteorExecutor（:20-30）：`newCachedThreadPool` daemon 线程——全部后台任务（TunnelESP/BlockESP 搜索、Notebot 解码、Capes）的家。
- Http（`Http.java`）：java.net.http.HttpClient+**虚拟线程执行器**（:33-35）；固定 Chrome UA（:53）；`send*` 同步、非 200 返 null（:130-133）；**未设超时**（依赖 HttpClient 默认）`[推断: 无限等待风险]`。

### B9. NametagUtils.to2D — 世界→2D 投影（`utils/render/NametagUtils.java:48-81`）

```
scale ×= zoom × clamp(1−dist×0.01, 0.5, ∞)      距离缩放(:113-116)
vec4 = pos − camera → ×modelView → ×projection   (:59-62)
w<=0 → 相机后方, 拒绝或翻转(:64-75)
透视除法 toScreen → ×窗口宽高 → y 翻转            (:69-79,118-125)
```

### B10. EChestMemory — 末影箱内容记忆（`utils/player/EChestMemory.java`）

**不监听任何包**——纯事件状态机：BlockActivateEvent（末影箱）置 state=1（:37-39）→ OpenScreenEvent 出现容器屏置 2（:42-45）→ 下一事件从 ChestMenu 复制 27 格到静态 ITEMS（:49-59）；GameLeftEvent 清空。被 BetterTooltips 的末影箱预览消费。

### B11. WireframeEntityRenderer 与 OutlineRenderCommandQueue 的分工

- **WireframeEntityRenderer**（`utils/render/WireframeEntityRenderer.java:43-127`）：调用原版 `createRenderState+submit` 但传伪造 `InterceptingStorage`（:71-101），把 submitModel/submitCustomGeometry 顶点重定向到 MyVertexConsumer——**每 4 顶点凑四边形调 Renderer3D.side 直绘**（:103-127），坐标加 lerp 偏移+原版 renderOffset。ESP 的 Wireframe 模式用。
- **OutlineRenderCommandQueue**（`utils/OutlineRenderCommandQueue.java:37-115`）：继承原版 SubmitNodeStorage，`order(i)` 覆写换内部 BatchingQueue（依赖 classtweaker 的 `submitsPerOrder` 字段），屏蔽 shadow/nameTag/text 等提交、统一染色——供 POST_OUTLINE 后处理描边。ESP 的 Shader/Glow 模式用。
- **分工**：Wireframe=手动画线（即时）；Outline=借原版提交通道+后处理（与原版渲染含动画姿态完全同步）`[推断]`。

## E. 演进考古（源码残骸与工程决策）

1. **@Redirect 绝迹**：全库 0 处——全用 MixinExtras（@ModifyExpressionValue 66/@WrapOperation 8 等）。`[推断]` 多 mod 环境下 Redirect 易冲突。
2. **classtweaker 自研格式**：`classTweaker v1 official` 头+18 条 accessible+逐条 `#` 用途注释——非 Fabric accesswidener。
3. **postprocess 包消失**：renderpearl 重写拆散——管线进 MeteorRenderPipelines（POST_OUTLINE/BLUR_*），逻辑内联（Blur 自管 6 级 FBO 金字塔）。
4. **死代码**：`sodium/MeshVertexConsumerMixin.java` 未注册进任何 mixins.json。
5. **TickRate 抄袭自 KAMI Blue**：注释原文（`utils/world/TickRate.java:19`）"copied from KAMI Blue LagCompensator"。
6. **DownloadQueueMixin 注释标注来自 LiquidBounce**：按账号 UUID 隔离资源包缓存（防指纹，取自他客户端）。
7. **Voyager 前置探测**：寻路层去 Baritone 化进行中（Voyager 不在仓库）。
8. **Baritone fork 版本错位**：本地 26.3-SNAPSHOT vs 声明 26.1-SNAPSHOT。
9. **NBT 而非 JSON**：9 个 .nbt 系统；`[推断]` 原生支持嵌套设置树，代价不可手编。
10. **tag 1337 协议**：Criticals↔NoFall 隐式互认（见 A5）。
11. **TheAltening**：密码常量 "Meteor on Crack!"，作者注释 *"todo i will eat my sock if this actually works"*（`TheAlteningAccount.java:72-74`）。
12. **OnlinePlayers 心跳**：每 5 分钟 POST online/ping，开游戏即跑。
13. **BookBot/Spam/Suffix 默认文案全是 "Meteor on Crack!"**——作者彩蛋贯穿。
14. **Metallum 兼容**：IGpuDevice 四后端多态（vanilla GL/Vulkan/Frontend + 第三方 Metallum）。
15. **HighwayBuilder 的 todo 自嘲**："do something about god damn lava flowing in"（:472-477）。
16. **Freecam 注册在 Render 类**且带 baritone-click——与 Wurst 同名模块的功能分化代表。
